## 1.26.0 — 2026-10-21

- Add one workspace-owned action proposal for a concrete external verification retry. A proposal records an immutable canonical intent (repository, workflow, run, commit SHA, expected attempt, designated executor, expiry, reason, and cited local evidence) and its SHA-256 digest. A human workspace owner approves or rejects that exact intent through the CLI; approval binds the normalized intent, evidence, and executor, and edits require a new proposal. An approved proposal has exactly one dispatch reservation for its provider target and attempt, and submission receipts distinguish accepted, definite failure before submission, and unknown. A submission receipt is not proof the tests passed, a lost response is never retried automatically, and failure/cancelled outcomes never appear as success.
- Add the eight service methods, six MCP tools, and `campfire actions` CLI surface: `propose`, `approve`, `reject`, `cancel`, `reserve`, `receipt`, `inspect`, `list`, and `receipts`, with bounded structured JSON inputs that are never executed, explicit revision/digest/request-key mutations, and cursor-bounded reads. `review_action` and `cancel_action` are deliberately absent from MCP: human approval and cancellation are CLI-only, and an agent token cannot approve even through direct `/v1/call`. Catalog entries describe the installed paths, the human-only review precondition, and the unavailable MCP approval surface.
- Add operator-bound `POST /v1/integrations/github/:sourceId` ingress on the local serve and Worker paths. Raw-byte HMAC-SHA256 verification, a 256 KiB body bound, a ten-second read deadline, source-authority fingerprint binding, semantic deduplication, and atomic follow-up create exactly one cited Finding and one Artifact reference for a valid `workflow_run` completion correlated to a reserved proposal. Redelivery returns the existing receipt; unsigned, replayed, uncorrelated, or conflicting deliveries create no workspace records. Raw webhook bytes are discarded and no body is logged.
- Keep the release bounded and redacted: Campfire stores no GitHub credential, makes no GitHub API call, and adds no `execute`, `run`, GitHub dispatch endpoint, provider polling loop, new Viewer tab or write path, or new outbound event name. The eight existing outbound event names are unchanged. The ingress is disabled unless one complete operator source binding exists, requires a dedicated existing integration agent with a registered live session, uses a secret distinct from the outbound webhook secret, and cannot rebind a used source id to another workspace or target.
- Record the result: **CONDITIONAL GO — engineering candidate.** D1–D9 pass on the recorded candidate, including the full suite, typecheck, build, isolated packaging, a 391-file audited public export, 19 frozen fixture checks, and a deployment dry run. Live Codex and OpenCode sessions are **NOT OBSERVED**, the real-provider round trip is **NOT AUTHORIZED**, and Step 0 was captured with partial product code already uncommitted. This release does not claim provider interoperability, live cross-harness continuation, human demand, or usefulness, and it moves no gate.

## 1.25.0 — 2026-10-20

- Add bounded capability discovery over the installed interface: `campfire capabilities --search <query> [--limit <1..10>] [--output auto|human|json]` and the read-only MCP tool `discover_capabilities({query, limit?})` return the same versioned `capability_search` projection. Entries name a stable logical id, purpose, effect, scope, required inputs, preconditions, output caveat, and an explicit CLI and/or MCP invocation. An interface absent on one surface is marked unavailable instead of fabricated. Search is deterministic, limited to 8 entries by default and 10 maximum, capped at a 16 KiB projection, and never opens a store or evaluates a query as a regex, shell command, URL, or program. It may run before workspace selection and exposes no workspace name, id, row count, membership verdict, token, secret, environment value, or credential receipt. A catalog entry is not a grant; the invoked operation still enforces authorization.
- Add two static read recipes through `campfire capabilities --recipe <id>` and the read-only MCP tool `get_read_recipe({id})`: `continue-blocked-work` follows existing authorized reads from workspace selection through bounded orientation, task paging, the selected task, and only its recorded citations; `review-decision-basis` follows an authorized orientation or bounded decision page into the selected decision, its recorded basis, and the cited findings' currentness. Each step names a prior result or client selection as its input source, an existing read invocation or an explicit unavailable surface, a stop rule, and a coverage caveat. The CLI stops and labels the record-history gap where `get_record_history` is MCP-only. Recipes are guidance for the current client: they are not stored in a workspace, do not run on the server, do not write, and do not precompute a handoff.
- Keep the released interfaces compatible: unqualified `campfire capabilities --output json` still returns the version-1 `cli_command_manifest` with only additive variant descriptions on its `capabilities` entry; existing direct-call output, MCP tool names and schemas, HTTP `/v1/call` contracts, the Viewer read allowlist, session instructions, and the opt-in playbook gate are unchanged.
