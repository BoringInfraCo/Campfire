# SHR-001 scoped multi-tenant restore drill

**Run:** October 25, 2026, 13:12–13:18 UTC
**Scope:** Rehearsal D1 export, imported into a new temporary remote D1, plus a synthetic second tenant, then a re-apply of the original export
**Result:** **PASS.** Restoring tenant A left tenant B intact. This does not change the v1.26.2 release decision.

The drill did not write to `campfire_shr001_rehearsal` or production D1 `campfire`, did not change a Worker binding, and did not deploy a Worker. The temporary database was deleted after verification. Wrangler was the project-local `4.149.0` binary. It was not upgraded. Command shape follows [Cloudflare's D1 import and export guide](https://developers.cloudflare.com/d1/best-practices/import-export-data/): `d1 export --remote --no-data` and `--no-schema`, then `d1 execute --remote --file`.

The scoped restore rewrote those statements to `INSERT OR REPLACE` and executed that file on the temporary D1 only (60 queries, including the export's `PRAGMA defer_foreign_keys=TRUE`).

## Source unchanged

After tenant B was inserted and restored, and before the temporary database was deleted, a second read-only schema export and data export of `campfire_shr001_rehearsal` were byte-for-byte identical to the first. Both schema hashes and both data hashes were the values in the table above. `d1 info` still reported 37 tables and 495,616 bytes, UUID ending `a66b87`. That covers this run only. It does not make two sequential exports atomic if the source is being written by someone else.

After `wrangler d1 delete` of `campfire_shr001_scoped_20261025_1312`, a lookup for that name failed. A further read-only `d1 info` of `campfire_shr001_rehearsal` still reported 37 tables and 495,616 bytes. Production `campfire` was not created, exported, executed, or deleted.

## What this does not prove

1. The source still has one real tenant. Tenant B is a synthetic fixture in a disposable database, not a second hosted customer and not an API authorization test.
2. The restore re-applied the whole original export. It is collision-safe against tenant B because those rows were not in the export. It is not a product feature that exports one tenant out of a database that already contains two.
3. No Worker binding, route, credential, or invitation was cut over. Existing rehearsal credentials were not copied into the evidence and were not reused for tenant B.
4. The one-file schema-plus-data import path remains the unreliable path from the full-clone drill. This pass used schema, then data, then `INSERT OR REPLACE` of the data export.
